# ADR-0031: Очистка обложек после изменения ссылок

- **Status:** Accepted
- **Date:** 2026-11-15

## Context

Удаление карточек и объединение дублей оставляли картинки в covers. Прежняя
очистка при смене расширения выполнялась до записи новой ссылки и удаляла файл
по имени, не проверяя, используется ли он другой сущностью.

## Decision

`cleanupUnreferencedCovers` получает конкретные прежние пути. После успешного
сохранения/удаления/commit объединения он сверяет ссылки всех Movie и Franchise,
включая черновики и скрытые фильмы, и удаляет только непривязанные изображения
из covers. Эквивалентные пути нормализуются; выход за пределы covers запрещён.
Ошибка чтения ссылок запрещает удаление. Сбой очистки логируется, но не отменяет
уже подтверждённую операцию БД. JSON-индекс обновляется после удаления.

При загрузке прежняя обложка удаляется после сохранения новой ссылки. Это
относится и к старому пути с чужим ID, полученному после объединения. При ошибке
записи новой ссылки выполняется проверка и уборка нового непривязанного файла.
Существующие файлы с другими расширениями сохраняются, если ещё используются.

Объединение сохраняет выбранный coverPath напрямую: имя файла не является
владельцем. Копирование под ID оставшейся карточки больше не выполняется.
После commit проверяются обе прежние обложки. `mergeMovies` владеет своей
транзакцией и принимает PrismaClient, а не внешнюю незавершённую транзакцию.

`withCoverMutation` сериализует операции записи обложек, изменения ссылок,
удаления и объединения через межпроцессную блокировку proper-lockfile. Это
не позволяет параллельной очистке удалить только что записанную картинку до
обновления её ссылки. Блокировка индекса метаданных остаётся отдельной.

## Consequences

Общие изображения не удаляются, пока существует хотя бы одна ссылка. Схема БД
не меняется. БД и файловая система не образуют общую транзакцию: аварийное
завершение процесса всё ещё может оставить файл, поэтому очистка рассматривает
только известные кандидаты и предпочитает сохранить файл при ошибке проверки.

Проверки на изолированной SQLite и временных файлах покрывают удаление последней
ссылки, общие обложки фильма/франшизы, оба выбора при merge, ошибку merge/сохранения,
JPG → PNG, старые пути после merge, нормализацию, JSON-индекс и параллельные загрузки.
