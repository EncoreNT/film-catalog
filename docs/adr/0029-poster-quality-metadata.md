# ADR-0029: Качество постеров и метаданные вне SQLite

- **Status:** Accepted
- **Date:** 2026-11-15

## Context

Нужно видеть, какие обложки каталога стоит заменить, и автоматически обновлять
оценку после замены. Пользователь явно исключил изменение схемы БД и хранение
новых метаданных в SQLite. Уже сохранённые изображения нельзя пересжимать ради
инвентаризации.

## Decision

Храним производный индекс `data/covers/poster-metadata.json`: версия формата,
время обновления и записи по имени файла. Запись содержит ширину, высоту, формат,
размер в байтах, `mtimeMs`, `ctimeMs`, время проверки и состояние чтения. Sharp
читает только метаданные; ориентация EXIF учитывается, для анимации используется
высота одного кадра. Первичное заполнение выполняется при открытии вкладки или
командой `npm run posters:index`. Файлы изображений и SQLite при этом не меняются.

`poster-metadata.ts` — единственный владелец индекса. Запись атомарна через
временный файл и rename; `proper-lockfile` сериализует refresh/upsert между
процессами web-сервера, CLI и фоновых задач. При обычной проверке повторно читаем
только изменившиеся файлы (size/mtime/ctime); принудительная проверка перечитывает
все. Отсутствующий, повреждённый или устаревший индекс восстанавливается из файлов.
Исчезнувшие файлы удаляются из индекса. Статистика до и после чтения защищает от
кэширования результата во время записи обложки.

Общий `saveEntityCoverBuffer` обновляет индекс после сохранения файла: это
покрывает загрузку вручную, Kinorium, извлечение из MKV и обложки франшиз.
Копирование обложки при объединении фильмов вызывает тот же helper отдельно.
Сбой производного кэша не отменяет уже записанную обложку: ошибка логируется,
следующая проверка повторяет чтение.

`getPosterQualityReport` соединяет существующий `Movie.coverPath` с индексом;
SQLite используется только для чтения. GET `/api/covers/quality` выполняет
обычную проверку, POST — принудительную. Ответы не кэшируются браузером.
Группы вычисляются на лету по области 2:3, видимой в карточке фильма:
`min(width, height × 2/3)` меньше 600 — низкое разрешение, от 600 до 1200 —
среднее, от 1200 — высокое. Отсутствующие и нечитаемые файлы вынесены отдельно.
Это оценка разрешения, а не резкости или артефактов сжатия.

Вкладка `/settings?tab=posters` по умолчанию показывает каталог, с поиском по
названию и переключением на черновики/скрытые/все фильмы. Сворачиваемые группы
выводят по 20 строк с догрузкой; качественные постеры изначально свёрнуты.
Строка показывает миниатюру, название, год, размеры, вес, формат и переход
«Заменить» в существующий редактор. При возвращении во вкладку данные обновляются.

### UI references

Опираемся на существующую страницу настроек, `StoragesSection`, `MachinedCard`
с `variant="calm"`, общий `SegmentedControl` и строки фильмов. Сохраняем токены
угольной палитры, золотой акцент, Manrope/Fraunces и штатные состояния фокуса.
Рекомендации Refero по постепенному раскрытию длинных списков применены через
группы и порционное отображение; на узком экране параметры переносятся под
название. Отдельные карточки на каждый фильм и новая цветовая система не нужны.

## Consequences

**Плюсы:** нет миграций и новых полей БД; индекс можно удалить и восстановить;
данные обновляются при сохранении и подхватывают внешние изменения файлов.
Метаданные франшиз тоже индексируются, но список качества относится к фильмам.

**Минусы / trade-offs:** размеры не выявляют апскейл, размытие или плохое JPEG
сжатие. Первичное чтение занимает время пропорционально числу обложек; следующие
проверки выполняют stat для каждого файла. Повреждение данных после заголовка
изображения может потребовать визуальной проверки.

**Validation:** тесты порогов и нестандартных пропорций, восстановление индекса,
EXIF, обновление/удаление файлов, конкурирующие записи и смена расширения обложки;
проверка интерфейса и реального сохранения на копиях БД и covers.
