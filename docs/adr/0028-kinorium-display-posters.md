# ADR-0028: Подготовка постеров Kinorium для каталога

- **Status:** Accepted
- **Date:** 2026-11-15
- **Supersedes:** ADR-0027 в части скачивания оригиналов; поиск, браузерное окно,
  отдельный профиль, CDN allowlist и подтверждение обложки сохраняются.

## Context

Оригинал «Холодного сердца» 5250×7874 с Kinorium — CMYK JPEG размером 65 333 544
байта (62,3 МиБ). Прежний лимит 10 МиБ возвращал 413. Пользователь предпочёл
уменьшать новые постеры, чтобы не хранить десятки мегабайт на обложку.

На этом файле WebP quality 85 дал: 1200×1800 — 543 236 байт;
1600×2400 — 961 012 байт; 2000×3000 — 1 573 962 байта. У среднего варианта
достаточно детализации для крупного просмотра в каталоге и экранов с высокой
плотностью пикселей, а файл примерно в 68 раз меньше исходника.

## Decision

`kinorium-client.ts` принимает исходное изображение до 100 МиБ с таймаутом 90
секунд на весь ответ. Это временный вход для обработки, не размер обложки на диске.
Поиск/HTML сохраняют свои небольшие лимиты и таймаут 12 секунд.

`GET /api/covers/kinorium/image` вызывает `prepare-kinorium-poster.ts` перед
ответом браузеру. Sharp применяет ориентацию, сохраняет пропорции без обрезки,
ограничивает длинную сторону 2400 px, не увеличивает маленькие изображения и
кодирует статичный WebP quality 85. Цвет приводится к sRGB; EXIF и печатные
метаданные не сохраняются. Вход ограничен 80 мегапикселями. Sharp добавлен как
явная runtime dependency, несмотря на присутствие через Next.js.

В браузер поступает готовый WebP, затем существующий File → preview → multipart
upload сохраняет те же байты. Повторного кодирования при сохранении нет.
Подписи сетки показывают исходные размеры на сайте; подсказка объясняет ресайз,
а предпросмотр показывает фактические размеры. Версия query в URL скачивания
отделяет результат от ранее закэшированных оригиналов.

Общий лимит обычной загрузки обложки остаётся 10 МиБ. Старые файлы, ручная загрузка,
извлечение MKV, SQLite и схема не меняются. Оригинал Kinorium не сохраняется на
диск приложением. Обработка выполняется только при выборе нового постера.

## Consequences

**Плюсы:** проблемный 62-МиБ постер можно выбрать; Windows-браузер и каталог
получают компактное изображение; сжатие и сохранение работают без миграций.

**Trade-offs:** обработка lossy; файл предназначен для просмотра, не печати.
Вес зависит от деталей изображения, фиксированного целевого числа байт нет.
Сервер в WSL всё ещё скачивает оригинал и затрачивает память/CPU на обработку.
Существующие обложки автоматически не пересжимаются.

Параметры Sharp: [resize](https://sharp.pixelplumbing.com/api-resize/),
[WebP / metadata](https://sharp.pixelplumbing.com/api-output/).
