# Film Catalog

Домашний каталог фильмов на Next.js 16 + SQLite. Сканирует папку с видеофайлами, определяет технические параметры через ffprobe, позволяет вручную дополнять метаданные и обложки.

## Требования

- **Node.js** 20.18.1+
- **FFmpeg** с `ffprobe` и `ffmpeg` в PATH
- **MKVToolNix** с `mkvmerge` в PATH (для сборки пользовательских релизов)

```bash
# macOS
brew install ffmpeg mkvtoolnix
```

## Быстрый старт

```bash
npm install
npm run db:migrate
npm run dev
```

`npm run dev` запускает **web + worker сборок** (очередь MKV-релизов). Только UI:

```bash
npm run dev:web
```

Worker отдельно:

```bash
npm run worker:builds
```

> **Node 24 + worker:** если worker падает с `ERR_PACKAGE_PATH_NOT_EXPORTED` / `unicorn-magic`, выполните `npm install` — в `package.json` есть override `npm-run-path@5.3.0` для совместимости `tsx` + `execa`.

Откройте [http://localhost:3000](http://localhost:3000).

## Настройка папки сканирования

Два способа:

1. **Через UI** — страница «Скан» (`/scan`), укажите абсолютный путь к папке с фильмами.
2. **Через `.env`**:

```env
DATABASE_URL="file:./data/catalog.db"
SCAN_ROOT="/path/to/your/movies"
```

## Где хранятся данные

| Путь | Содержимое |
|------|------------|
| `./data/catalog.db` | SQLite база |
| `./data/covers/` | Обложки фильмов |

Папка `data/` в `.gitignore`.

## Возможности

- Рекурсивное сканирование видеофайлов (один файл = один релиз; фильм может иметь несколько релизов)
- Автоопределение: разрешение, кодек, HDR, FPS, битрейт видео, продолжительность
- Аудиодорожки: кодек (AC3/E-AC3/TrueHD/DTS…), профиль (Atmos/HD MA…), формат (2.0/5.1/7.1), битрейт, язык
- Субтитры: тип (SRT/ASS/PGS/VobSub…), язык, forced
- Жанры: несколько жанров на фильм, фильтр по жанрам в каталоге
- Черновики (Draft) → апрув в каталог
- Дедупликация: быстрая проверка size+mtime, хэш префикса при конфликте
- Личная оценка (1–10) и дата просмотра
- Франшизы: слоты, quality reel, completion meter, привязка фильмов
- Фильтры: жанр, разрешение, язык аудио, формат звука, оценка, просмотренность, сортировка по продолжительности
- Загрузка обложек локально (фильмы 2:3, франшизы 16:9)
- Поиск постеров Kinorium по названию и году, без API-ключа
- **Сборка релизов**: выбор дорожек из нескольких исходных Release, AC-3/E-AC3 transcode, фоновая очередь (`/builds`)
- UI: дизайн-система **Cinematic Tech** — см. [`docs/design-system.md`](docs/design-system.md)

### Постеры Kinorium

В редакторе фильма нажмите на обложку и выберите **Kinorium**. Название берётся из
текущих полей формы; можно изменить запрос или искать по оригинальному названию.
Выберите нужный фильм, затем постер и подтвердите сохранение внизу окна.
Под постерами показаны размеры исходников. Выбранный постер сервер уменьшает до
2400 пикселей по длинной стороне и преобразует в WebP с качеством 85, сохраняя
пропорции; небольшие картинки не увеличиваются. В предпросмотр и каталог попадает
уже подготовленная копия. Например, постер 5250×7874 весом 62,3 МБ становится
1600×2400 и 0,92 МБ. Исходник до 100 МБ скачивается только для обработки;
обычный лимит загрузки обложки остаётся 10 МБ. Старые обложки не пересжимаются.

Основной постер доступен через поиск. Дополнительные постеры загружаются из галереи,
если Kinorium разрешает доступ. Если сайт требует проверку, нажмите **«Загрузить
через браузер»**. Откроется отдельное видимое окно Chromium на компьютере, где
работает web-сервер каталога. Пройдите капчу вручную, если она появится; каталог
дождётся галереи (до трёх минут), перенесёт постеры в окно выбора и закроет Chromium.
Кнопка «Отменить ожидание», возврат к фильмам и закрытие выбора обложки прекращают
ожидание. Можно закрыть и само окно Chromium, затем повторить попытку.

Один раз установите браузер в том же окружении, где запускаете каталог:

```bash
npm run kinorium:browser:install
```

На Linux / WSL команда также устанавливает системные библиотеки Chromium и может
запросить пароль `sudo` в терминале. После установки перезапустите web-сервер.
На Linux / WSL нужен графический сеанс (например, WSLg). На сервере без дисплея
останутся поиск основного постера и обычная загрузка файлов/ссылок. Cookies
Kinorium хранятся в отдельном профиле `data/kinorium-browser/` (gitignored), чтобы
сохранять пройденные проверки; личный профиль Chrome не используется. Сайт может
запросить проверку повторно. Открывается одно окно за раз. Встраивание сайта в
`iframe` не используется: Kinorium запрещает его через `X-Frame-Options: SAMEORIGIN`.

Если каталог работает в WSL, а вы открываете его в Chrome/Edge на Windows,
выполняйте установочную команду **в терминале WSL**. Дополнительное окно Chromium
тоже работает в WSL и отображается на рабочем столе Windows через WSLg. Это
отдельная сессия: вход и проверки, пройденные в вашем Windows-браузере, в неё не
переносятся. Капчу при необходимости проходите именно в дополнительном окне.

Для этой возможности не нужны ключ, учётная запись Kinorium или миграции БД.
После обновления существующего каталога нужны `npm install`, установка браузера
для этого способа и перезапуск web-сервера. Поиск и предпросмотр не меняют каталог;
подтверждённая обложка
использует существующее хранилище `data/covers/` и поле `coverPath`.

### Качество постеров

В **Настройки → Качество постеров** (`/settings?tab=posters`) фильмы сгруппированы
по разрешению обложки: низкое — меньше 600 × 900, среднее — от 600 × 900,
высокое — от 1200 × 1800. Учитывается область 2:3, видимая в карточке. Размеры
не заменяют визуальную оценку резкости и следов сжатия. Отдельные группы показывают
отсутствующие и нечитаемые файлы.

В списке есть поиск, фильтр каталога/черновиков/скрытых фильмов, размеры и вес
каждого файла и действие **«Заменить»**.
В каждой строке **«Заменить постер»** открывает общий выбор обложки
прямо в настройках (включая Kinorium). Название и миниатюра ведут на страницу фильма.
Все группы изначально свёрнуты; иконки и цветовые
статусы помогают отличать низкое, среднее и высокое разрешение, отсутствующие
и нечитаемые постеры. После сохранения
обложки метаданные обновляются автоматически; кнопка **«Обновить»** перечитывает
все файлы, например после ручной замены в папке.

Данные хранятся в `data/covers/poster-metadata.json`, без новых полей и миграций
SQLite. Первичная проверка запускается при открытии вкладки. Можно выполнить её
отдельно: `npm run posters:index`. Индекс восстанавливается при удалении или
повреждении; сами изображения эта проверка не меняет и не пересжимает.

### Сборка пользовательских MKV

- Конструктор: `/movies/[slug]/builds/new` — video copy, выбор audio/subtitle, опциональный transcode
- Очередь: `/builds` — статус, отмена, повтор
- Результат регистрируется как **новый Release** того же фильма; исходники не изменяются
- E-AC3/AC-3: пресеты битрейта, цель 2.0 или до 5.1 (7.1/Atmos downmix); Atmos в новой дорожке не сохраняется
- Совпадение длительности ≠ гарантия синхронизации; для audio copy доступен ручной сдвиг (мс)
